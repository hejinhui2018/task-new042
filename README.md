# CacheSketch · 缓存失效规划台

纯浏览器本地运行的 CDN 缓存失效规划工具：选择本次改动的路由、资源与缓存策略后，
系统依据 **surrogate key、引用关系闭包和 stale-while-revalidate 规则**，
计算失效范围与执行波次，把对象分为三类并给出**每条结论的依赖依据**，
还能逐波模拟边缘节点成功/超时、比较策略调整前后的范围、生成最小回退计划。

技术栈：**React 18 + TypeScript + Vite**，状态与计算全部在浏览器本地完成
（localStorage 持久化），无后端、无网络请求。

## 运行方式

```bash
npm install        # 安装依赖
npm run dev        # 启动开发服务器（默认 http://localhost:5173）
```

其他命令：

```bash
npm test           # 运行全部测试（Vitest，单次）
npm run test:watch # 测试监听模式
npm run build      # 类型检查 + 生产构建（输出到 dist/）

```

> 如遇 npm 缓存目录权限问题，可指定可写缓存：`npm install --cache /tmp/npm-cache`。

## 内置场景：春季活动页换肤（v1 ↔ v2 可回滚）

- `/spring/` 主会场与 `/spring/sub.html` 分会场本次换肤；首页 `/` 与 `/promo/` 不发布。
- 新组件包 `comp-v2.css`、新脚本 `app-v2.js`、新展示字体 `display-v2.woff2` 为**内容指纹新 URL**。
- 基础字体 `base-v1.woff2` **跨所有路由共享**，内容不变。
- 历史原因，新旧两代资源共用“宽” surrogate key：`css-components`、`js-app`、`img-hero`。
  直接按宽 key purge 会把首页/促销页仍在引用的旧副本一起打掉。

默认策略下规划结果：

| 分类 | 对象 | 主要依据 |
| --- | --- | --- |
| **必须立即清除（W1）** | 两个春季入口 HTML | R1：入口被选中发布，`no-cache`，必须硬切断旧文档 |
| **可延迟刷新（W2）** | 皮肤 CSS（稳定 URL，SWR）、新展示字体、新/旧主视觉 | R5：SWR 窗口内后台刷新；R4：指纹新 URL 无需清除；R6：无引用方旧副本连带清除安全 |
| **不能安全清除（W3）** | 基础字体、旧组件包、旧脚本、新组件包、新脚本 | R2：仍被未发布页面引用；R3：宽 key 会误伤旧副本 |

## 判定规则（每条结论都可在卡片上看到规则码与依赖对象）

| 规则 | 含义 |
| --- | --- |
| **R1-entry-selected** | 入口 HTML 属于本次发布路由：必须立即失效（除非该路由显式允许 SWR 软失效） |
| **R2-shared-by-untouched** | 对象仍被本次不发布页面的引用闭包覆盖，清除会造成字体/样式回退与回源抖动 |
| **R3-surrogate-key-collision** | 对象携带的 surrogate key 在边缘还命中“未发布页面仍在引用”的副本，按 key purge 会误伤 |
| **R4-fingerprinted-immutable** | 内容指纹 + immutable 资源：新内容在新 URL，首请求自然回源，**无需主动 purge** |
| **R5-stale-while-revalidate** | SWR 资源：旧副本可继续服务，容忍窗口内后台异步刷新 |
| **R6-collateral-safe** | 同 key 的其它副本已无未发布引用方，随 key 连带清除安全 |

结论优先级：`unsafe-keep > purge-now > stale-refresh`。
被判定 unsafe 的对象**不会产出任何 purge key/URL**；发生碰撞的 key 也会从 purge 集合中剔除，
卡片同时给出处置建议（逐 URL purge、收窄 surrogate key，或等引用页面一并发布）。

### 波次顺序

1. **W1 · 立即清除**：入口 HTML（及容忍窗口为 0 时的 SWR 资源）。全部区域成功后才放行 W2。
2. **W2 · 延迟刷新**：SWR 资源软清除 + 指纹新资源预热；超时不阻塞发布，窗口内收敛即可。
3. **W3 · 不操作**：unsafe-keep 对象只展示理由与处置建议，不生成任何执行动作。

## 功能说明

- **策略调整**：勾选路由、允许入口 SWR、开关 surrogate key 批量失效、调整 SWR 容忍秒数/
  超时/重试次数，还可逐资源覆盖缓存策略。规划实时重算。
- **前后对比**：在「前后对比」页钉住当前规划为基线，再调整策略，可看到结论迁移
  （如 unsafe-keep → stale-refresh）、移出/新增进范围的对象。
- **逐波边缘模拟**：5 个区域 × 每波对象的矩阵，可手动标记 ✓成功 / ×超时；
  超时在重试预算内可继续重试，耗尽后成为终态失败；也可一键**确定性自动模拟**（同 seed 可重放）。
  W1 失败会阻塞 W2，W2 失败不阻塞发布；事件流按序记录每次尝试。
- **最小回退计划**：只对前向发布中**确实已成功改变**的 区域×对象 生成反向 purge：
  前向超时/未执行的区域仍持有旧副本，零操作；指纹新资源永不被旧文档引用，跳过。
  顺序上先恢复 W2 稳定 URL 资源、最后硬清除 W1 入口。切换发布版本到 v1 也等价于规划一次回滚发布。
- **撤销 / 重做**：所有策略编辑进入历史栈（Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl+Y）。
- **刷新恢复**：文档与模拟结果自动存入 localStorage；模拟记录带规划指纹，
  策略变化导致规划改变时旧模拟自动作废并重建。
- **重置**：清空历史、模拟与本地存储，回到内置场景默认值。
- **稳定输出**：所有集合在输出层排序，对象经键排序后序列化；规划附带 8 位指纹，
  语义相同的规划指纹恒定。

## 目录结构

```
src/
  domain/            纯领域逻辑（无 React 依赖，可独立测试）
    types.ts         类型定义
    scenario.ts      内置“春季换肤”场景（v1/v2）与边缘区域
    graph.ts         引用图、依赖闭包、边缘新旧副本并集
    plan.ts          失效分类（R1–R6）、purge 范围与波次生成
    simulate.ts      边缘执行模拟：重试、波次门禁、确定性自动模拟
    rollback.ts      最小回退计划
    compare.ts       前后规划对比
    canonical.ts     稳定序列化与规划指纹
  state/history.ts   撤销/重做 reducer 与 localStorage 持久化
  ui/                React 展示组件（策略面板/规划面板/模拟/对比/回退）
  App.tsx            组装与交互编排
test/                Vitest 测试（53 个用例）
```

## 测试覆盖

`npm test` 覆盖：

- **依赖闭包**：传递依赖、跨多跳字体引用、与种子顺序无关、未发布闭包、新旧版本并集、反向边；
- **波次顺序**：三类分组与稳定排序、SWR 窗口为 0 时的波次迁移、W3 不产出 purge key；
- **超时重试**：预算内可重试、耗尽后终态锁定、成功不可回退、W1 门禁、确定性自动模拟；
- **最小回退**：无记录时的最坏情况、回退顺序、按前向结果裁剪（超时/未执行零操作）、指纹资源跳过；
- **稳定输出**：键排序序列化、数组顺序保留、规划指纹敏感性、相同输入逐字节一致；
- **撤销/重做**与整页 **React 冒烟渲染**。
