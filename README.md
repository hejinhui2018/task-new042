# CacheSketch 缓存失效规划台

面向前端发布团队的 CDN 缓存失效规划工具。解决的真实痛点：发布时只清了入口 HTML，
旧的字体和组件样式仍从边缘节点返回，导致部分地区长时间看到不一致的页面。

CacheSketch 根据 **surrogate key、资源引用关系（依赖闭包）和 stale-while-revalidate
规则** 计算本次发布的失效范围与执行波次，把每个对象分为三类并给出可追溯的依据，
然后逐波模拟边缘节点的清除执行（成功 / 超时 / 重试 / 失败），并生成最小回退计划。
全部计算在浏览器本地完成，无任何服务端依赖。

## 运行方式

环境要求：Node.js ≥ 18（开发使用 Node 22 验证）。

```bash
npm install        # 安装依赖
npm run dev        # 开发服务器（默认 http://localhost:5173）
npm test           # 运行全部测试（vitest，43 个用例）
npm run build      # 类型检查 + 生产构建（输出到 dist/）
npm run preview    # 预览生产构建产物
```

## 内置场景：春季活动页换肤

本次发布：落地页与促销子页 HTML 重新发布（r2026.03.12 → r2026.03.19），
`spring-theme.css` 升级 v1 → v2，主视觉 `spring-hero.avif` 升级 v1 → v2。

| 资源 | 说明 | 策略要点 |
| --- | --- | --- |
| `html.spring` / `html.spring-promo` | 活动页入口 HTML | 短 TTL；子页带 SWR 300s |
| `css.spring` (v2，可回滚 v1) | 春季皮肤 | 依赖品牌字体 |
| `css.base` (v8，可回滚 v7) | 基础组件样式，**跨路由共享** | SWR 600s |
| `font.brand` (v5，可回滚 v4) | 品牌字体，**跨路由共享** | SWR 3600s |
| `js.components` (v8) | 共享组件脚本 | 无可回滚版本 |
| `img.hero` (v2，可回滚 v1) | 春季主视觉 | 长 TTL |
| `img.logo` | 品牌 Logo | **immutable**（哈希寻址） |
| `html.home` / `html.about` | 首页 / 品牌页（不在本次发布内） | 引用共享字体与样式 |

建议的探索路径：

1. 默认选择即完整换肤发布（两个春季路由 + 皮肤 CSS + 主视觉），观察波次分层；
2. 勾选 `font.brand`（品牌字体）——字体本身与首页/品牌页 HTML 被判为
   **不能安全清除**，`css.base` 因 SWR 进入**延迟刷新**；
3. 取消勾选 `route.spring-promo`——共享的皮肤 CSS 变为不能安全清除，
   子页 HTML 因 SWR 延迟刷新；
4. 调整「SWR 资源处理」「允许清除跨路由共享资源」，用**范围对比**查看前后差异；
5. 在模拟面板**注入典型故障**，逐波执行，观察超时重试与失败后的**最小回退计划**。

## 失效分类规则

每个对象的结论都附带依据（规则 + 依赖链 / surrogate key / 路由引用），
在界面上逐条展示。规则按优先级判定：

**变更对象**（显式选中的资源 + 选中路由的入口 HTML）：

1. `immutable` 策略 → **不能安全清除**（内容哈希寻址，应发布新 URL）；
2. 仍被未选中路由引用、且未允许跨路由清除 → **不能安全清除**；
3. 其余 → **必须立即清除**。

**间接受影响对象**（依赖闭包或共享 surrogate key 波及）：

4. 带 SWR 且策略为「延迟刷新」→ **可以延迟刷新**（窗口内自然再验证）；
5. 仍被未选中路由引用、且未允许跨路由清除 → **不能安全清除**；
6. 其余 → **必须立即清除**。

## 波次编排

「必须立即清除」的对象按依赖关系分层：**依赖方（入口 HTML）在前，被依赖的
共享资源（样式、字体）在后**，保证深层共享资源被清除时，上层引用方已经刷新，
边缘节点不会重新缓存到「新引用指向旧版本」的中间态。同一波内按资源 id 字典序
排序，输出确定。

## 执行模拟语义

- 每个（波次 × 边缘节点）是一个清除单元；点击单元格可注入「强制超时次数」；
- 一次尝试超时后进入重试，首次尝试 + `maxRetries` 次重试全部超时 → 单元失败，
  整个模拟停止在当前波次；
- 前一波全部节点成功后才推进到下一波；后续波次的单元在到达前不会被触碰；
- 执行日志按顺序记录每次尝试。

## 最小回退计划

模拟失败（或已有部分清除成功）时生成：

- 只包含**已在至少一个节点清除成功**的资源 —— 未执行的波次无需回退；
- 每个资源只列出**清除成功的节点** —— 失败/未触碰的节点无需处理；
- 步骤按原波次顺序（依赖方先回滚），目标版本取资源的 `rollbackVersion`；
- 没有可回滚版本的资源列入「无法自动回退」，需人工介入。

## 稳定输出

`serializePlan` / `planHash` 对同样的输入（与数组顺序无关）产生完全相同的
序列化字符串与 8 位十六进制哈希，不含时间戳或随机量，可用于 diff、审计与
回归校验。界面顶栏实时显示当前计划哈希。

## 撤销 / 重做 / 持久化

- 全部操作（选择、策略、故障注入、模拟执行）都可撤销（Ctrl/Cmd+Z）与重做
  （Ctrl/Cmd+Shift+Z），历史上限 100 步；
- 状态自动保存到 `localStorage`，刷新页面后恢复；
- 「重置」清空持久化状态并回到初始场景。

## 测试

`src/test/` 下的 6 个测试文件对应需求中的关键行为：

| 文件 | 覆盖 |
| --- | --- |
| `dependency.test.ts` | 依赖闭包：波及范围、依赖链、多变更源、循环依赖安全、遍历顺序确定 |
| `plan.test.ts` | 三分类规则优先级、跨路由共享、immutable、surrogate key 连带、波次顺序 |
| `simulate.test.ts` | 波次推进、波次门禁、超时重试、重试耗尽失败、日志顺序、自动执行 |
| `rollback.test.ts` | 最小集合（未执行波次/未成功节点不纳入）、回退顺序、无版本资源告警 |
| `stable-output.test.ts` | 输入顺序无关、重复计算一致、哈希格式、策略/选择变化改变哈希 |
| `store.test.ts` | 选择切换、模拟失效、故障注入循环、撤销/重做/重置 |

## 目录结构

```
src/
  types.ts               # 领域模型（资源/路由/策略/边缘节点）
  data/scenario.ts       # 内置场景：春季活动页换肤
  lib/
    dependency.ts        # 反向依赖闭包（BFS，记录依赖链）
    plan.ts              # 失效分类、波次编排、稳定序列化与哈希
    simulate.ts          # 波次执行模拟、超时重试、最小回退计划
  state/
    store.ts             # 应用状态与 reducer（纯函数）
    history.ts           # 撤销/重做历史
    persistence.ts       # localStorage 持久化（刷新恢复）
  components/            # 选择面板、失效范围、范围对比、执行模拟、回退计划
  test/                  # vitest 测试（node 环境，纯逻辑）
```
